0 · Preparar el entorno

Todos los comandos se lanzan desde la raíz del repositorio, en la rama session_07_live. El código Python corre dentro del contenedor estimator con docker compose exec. Los comandos sirven igual en bash y en PowerShell. Si en PowerShell salen avisos de librerías por la salida de errores, se pueden ocultar añadiendo 2>$null al final. 2 · Embeddings: el sanity check

scripts/compare.py
diapo 5
Para qué sirve. Embebe dos textos y calcula su similitud coseno a mano, sin numpy. Tres parejas: cercanas, sin relación y genéricas.
Comando
docker compose exec estimator python scripts/compare.py \
  --text-a "OAuth 2.0 authentication backend with JWT tokens for fintech mobile app" \
  --text-b "Authorization service using JSON Web Tokens for a banking application"
docker compose exec estimator python scripts/compare.py --text-a "OAuth 2.0 authentication backend with JWT tokens for fintech mobile app" \
  --text-b "Database migration from MySQL to PostgreSQL with zero downtime"
docker compose exec estimator python scripts/compare.py --text-a "Backend services" --text-b "API development"
Salida
Text A: OAuth 2.0 authentication backend with JWT tokens for fintech mobile app
Text B: Authorization service using JSON Web Tokens for a banking application
Cosine similarity: 0.5957

Text A: OAuth 2.0 authentication backend with JWT tokens for fintech mobile app
Text B: Database migration from MySQL to PostgreSQL with zero downtime
Cosine similarity: 0.1920

Text A: Backend services
Text B: API development
Cosine similarity: 0.5407
Cómo leerla.
  • 0,5957: el mismo concepto con casi ninguna palabra en común. Se queda justo por debajo de 0,6: los umbrales dependen del modelo y de la redacción.
  • 0,1920: temas sin relación, bien separados.
  • 0,5407: dos frases cortas y vagas salen casi tan «cercanas» como la primera pareja. Por eso cada chunk del proyecto lleva una cabecera con proyecto, sector y tecnología.

3 · La ingesta: de presupuestos a vectores

POST /embeddings/ingest
diapo 12
Para qué sirve. Trocea los presupuestos con la estrategia estructural (un componente = un chunk) y embebe cada chunk. Devuelve los chunks con su vector y las estadísticas. No se guarda nada: los vectores viven en memoria hasta la Sesión 8.
Comando
curl -s -X POST localhost:8000/embeddings/ingest -H 'Content-Type: application/json' \
  -d "{\"budgets\": $(cat estimator/data/budgets_sample.json)}" \
  | jq '{stats, primero: .chunks[0] | {chunk_id, token_count, text, metadata, dims: (.embedding | length)}}'
En PowerShell
$body = '{"budgets": ' + [IO.File]::ReadAllText("$PWD\estimator\data\budgets_sample.json") + '}'
$r = Invoke-RestMethod -Method Post -Uri http://localhost:8000/embeddings/ingest `
  -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$r.stats
$r.chunks | Select-Object -First 5 chunk_id, token_count, @{n='dims';e={$_.embedding.Count}}

4 · Dimensiones: 1536 frente a 768

compare_chunkers.py --models
diapo 10-11
Para qué sirve. El mismo modelo (text-embedding-3-small) pedido a 1536 y a 768 dimensiones (Matryoshka). Compara la latencia media y el coseno entre los dos primeros componentes.
Comando
docker compose exec estimator python scripts/compare_chunkers.py --models small-1536,small-768
Salida
Model comparison (latency per embedding + cosine of first two components):

model       dims  avg_latency_ms  cosine(c0,c1)
----------  ----  --------------  -------------
small-1536  1536  406.1           0.9119       
small-768   768   218.5           0.9116
Cómo leerla. El coseno apenas cambia (0,9119 frente a 0,9116) y el vector ocupa la mitad. La latencia de una sola ejecución varía mucho entre llamadas: no la tomes como dato fijo. Lo que no se puede hacer es comparar un vector de 1536 con uno de 768.

5 · Estrategias de chunking gratuitas

compare_chunkers.py pasa el mismo corpus por varias estrategias. Columnas: número de chunks; mínimo, p50, p95 y máximo de tokens por chunk; huérfanos (< 20 tokens, sin contexto) y obesos (> 800 tokens, mezclan temas). Los nombres de estrategia se escriben con guion: fixed-size, sentence-window.
structural frente a fixed-size
diapo 15, 19
Para qué sirve. La estrategia de referencia (un componente = un chunk) contra ventanas fijas de 512 tokens.
Comando
docker compose exec estimator python scripts/compare_chunkers.py --strategies structural,fixed-size --show-stats
Salida
strategy    n_chunks  min  p50   p95    max   orphans  obese
----------  --------  ---  ----  -----  ----  -------  -----
structural  60        57   78.0  96.5   1391  0        1    
fixed_size  63        57   79.0  108.7  512   0        0
Cómo leerla. Casi iguales: el corpus ya está estructurado y casi todos los componentes caben en 512 tokens. El obeso de structural es MONO-001, una descripción de 1.391 tokens que fixed-size parte en tres.
recursive
diapo 16
Para qué sirve. Separadores jerárquicos (párrafo → línea → frase → palabra) con un máximo de 512 tokens.
Comando
docker compose exec estimator python scripts/compare_chunkers.py --strategies recursive --show-stats
Salida
strategy   n_chunks  min  p50    p95    max  orphans  obese
---------  --------  ---  -----  -----  ---  -------  -----
recursive  23        10   187.0  488.5  494  1        0
Cómo leerla. 23 chunks: casi cada presupuesto entero cabe en uno, así que mezcla componentes distintos en el mismo vector. El huérfano es un trozo de 10 tokens con solo el nombre.

6 · Estrategias de pago y el Chunking Lab

Las tres estrategias que llaman a un modelo
diapo 21-23
Para qué sirve. semantic embebe durante la ingesta, propositional usa gpt-4o-mini y contextual_retrieval usa Claude (necesita ANTHROPIC_API_KEY). Con --strategies all, si falta la clave de Anthropic la ejecución entera falla: conviene listar las estrategias a mano.
Comando
docker compose exec estimator python scripts/compare_chunkers.py --strategies semantic,propositional --show-stats --show-cost
Salida
strategy              n_chunks  p50     orphans  obese  cost_usd  seconds
semantic              34        112,5   0        1      0,0001    5
propositional         778       11      765      0      0,0076    173
contextual_retrieval  60        132,5   0        1      0,14      203
(datos del informe estimator/app/generation/rag/COMPARISON_REPORT.md)
Cómo leerla.
  • propositional: 13 veces más chunks, casi todos huérfanos, y 3 minutos de ingesta; a cambio, scores muy altos en consultas concretas.
  • contextual_retrieval: la más cara (0,14 $ con este corpus pequeño) y la más lenta; mejora la similitud del chunk correcto sin cambiar el número de chunks.
  • semantic: barata, pero ya no es gratis ni instantánea.
Lo comprueba: docker compose exec estimator-web bin/rails test test/models/rag/strategy_test.rb
El Chunking Lab en la web
diapo 14
Para qué sirve. La misma comparativa con formulario: se eligen estrategias (las de pago van marcadas), consultas y top-k. Cada ejecución se guarda, así que las estrategias caras se pagan una sola vez.
Comando
http://localhost:3000/rag/chunking_comparisons/new      # nueva comparativa
http://localhost:3000/rag/chunking_comparisons          # histórico
Cómo leerla. En cada ejecución: la tabla de estadísticas, las barras de coste y el playground con los chunks recuperados por consulta. Las llamadas largas tienen un timeout de 600 s.
Lo comprueba: docker compose exec estimator-web bin/rails test test/controllers/rag/chunking_comparisons_controller_test.rb
